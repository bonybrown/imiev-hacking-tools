# 0x100

| Field          | Value      |
|----------------|------------|
| **Sender**     | EV-ECU     |
| **Recipients** | ETACS      |
| **Period**     | On demand  |
| **Length**     | 4          |

Immobiliser challenge from the EV-ECU. The payload contains two 16-bit values derived from an internal timer/counter value and sent in big-endian byte order.

Firmware computes:

```c
immo_a = immo_timer1_count ^ TMS1CT;
immo_b = immo_a * 5 + 0x77;
```

The message then transmits `immo_a` followed by `immo_b`.

---

## Signals

| Bytes | Signal | Type               | Notes |
|-------|--------|--------------------|-------|
| 0–1   | `immo_a` | uint16, big-endian | `immo_timer1_count ^ TMS1CT` |
| 2–3   | `immo_b` | uint16, big-endian | `(immo_a * 5 + 0x77) & 0xFFFF` |

## Example

For:

```text
100#C782E601
```

the decoded values are:

- `immo_a = 0xC782`
- `immo_b = 0xE601`

These satisfy:

```text
(0xC782 * 5 + 0x77) & 0xFFFF = 0xE601
```

The ETACS response to this challenge is carried in [0x111](111.md).
