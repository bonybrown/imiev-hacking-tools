# 0x111

| Field          | Value      |
|----------------|------------|
| **Sender**     | ETACS      |
| **Recipients** | EV-ECU     |
| **Period**     | On demand  |
| **Length**     | 3          |

Immobiliser response from ETACS to the EV-ECU. The EV-ECU compares the three received bytes against locally computed expected values derived from [0x100](100.md) and four VIN bytes stored in EEPROM shadow memory.

---

## Signals

| Byte | Signal              | Notes |
|------|---------------------|-------|
| 0    | `immo_received_c`   | First byte on the wire |
| 1    | `immo_received_b`   | Second byte on the wire |
| 2    | `immo_received_a`   | Third byte on the wire |

The EV-ECU receives the payload as:

```c
immo_received_c = pid_111_0;
immo_received_b = pid_111_1;
immo_received_a = pid_111_2;
```

so the on-wire order is `c, b, a`.

## Validation

The EV-ECU calculates:

- `immo_expected_a`
- `immo_expected_b`
- `immo_expected_c`

and then checks:

```c
if ((immo_received_a == immo_expected_a) &&
    (immo_received_b == immo_expected_b) &&
    (immo_received_c == immo_expected_c)) {
  ...
}
```

This confirms that `0x111` is the immobiliser key/response frame.

## Example

For:

```text
111#EDF80F
```

the EV-ECU interprets:

- `immo_received_c = 0xED`
- `immo_received_b = 0xF8`
- `immo_received_a = 0x0F`

See [EV-ECU immobiliser notes](../ev-ecu/immobiliser.md).
